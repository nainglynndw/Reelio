# Reelio contributor guide

Reelio is local-first. Keep generated media, uploaded tool inputs, models, state, and credentials under the configured `REELIO_DATA_DIR`; never add them to Git or send them to a hosted service unless the user explicitly selected a hosted provider.

## Workflow boundaries

- Keep Quick Create and Guided Create as separate UI surfaces that submit compatible `/jobs` records. Guided Create must pass its reviewed script as `approvedScript`, its reviewed visual plan as `visualThemes`, and exactly one validated `visualSelections` choice per theme so rendering never silently replaces approved work. Guided users may bypass token-consuming theme generation only through the local deterministic storyboard plan, which must still produce validated themes and explicit selections before rendering.
- Treat `scriptStyle` as a validated structural choice, not a loose prompt fragment. Preserve it through drafting, fact-editing, expansion, fallback writing, review, and job metadata; factual limits always override creative structure.
- For generated scripts, build quality in three stages: a grounded evidence dossier when Gemini Search is available, a topic-specific hook and beat plan, then drafting plus skeptical fact editing. The brief and evidence are the full factual boundary. Preserve supported names, dates, quantities, examples, mechanisms, and caveats during editing; do not flatten them back into generic language. If grounded search is unavailable, continue from the reviewed brief without inventing evidence.
- Use medium or high Gemini thinking for idea development, research, angle planning, script drafting, and fact editing. Use low thinking for deterministic-format work such as translation, visual-theme parsing, publishing copy, and other mechanical transformations. Approved Guided Create scripts must bypass all research and writing calls.
- Treat `narratorId` as a validated persona choice. Keep each narrator's Kokoro voice, Gemini voice, VoxCPM2 description, pace, tone, and displayed identity aligned. Environment voice values may replace personas only when `REELIO_BRAND_VOICE_OVERRIDE=true`; default provider values must not silently collapse every persona to one voice.
- Give every VoxCPM2 persona a distinct deterministic design seed and a language-specific calibration reference. For non-English speech, build the reference from actual text in the selected language, persist both its WAV and exact transcript under `REELIO_DATA_DIR`, and clone it for later cues so the speaker remains recognizable without reverting to English.
- Treat Brand Kit as a versioned local production preset, not a loose asset folder. Store its record and immutable uploads under `REELIO_DATA_DIR`, never expose trusted file paths through HTTP, and snapshot the active kit into each queued Quick Create, Guided Create, and opted-in Video Synthesis job. Replacing or removing the active asset must not alter or break an existing job snapshot.
- Brand Kit may direct script tone and publishing identity, but never override factual constraints or an approved Guided Create script. Preserve language-specific caption fonts, then apply the selected brand font to supported scripts, thumbnails, colors, motion fallbacks, logo, intro/outro, and music.
- Voice samples must synthesize the reviewed opening line with the selected narrator, language, and engine. Label local versus API usage before generation, require explicit confirmation before AI translation, cache identical samples for replay, and serialize preview work with other model-heavy jobs.
- Keep reusable media operations in `local-service/tools/`. A tool receives normalized options and resolved local input files, reports progress, and returns named assets plus metadata.
- Keep Quick Automation and Content Calendar as separate scheduling contracts. Quick Automation is a recurring cron pipeline; every occurrence must generate a fresh AI Suggested Idea or source-grounded Latest News brief before creating its job. Prevent overlapping Quick runs for the same pipeline, expose the next occurrence and latest outcome, and revalidate the template and publishing readiness each time it starts.
- Content Calendar follows durable dated entries, not a cron pipeline presented as a calendar. A pipeline defines a bounded start/end date, selected weekdays, and one to eight posting times per selected day. Allow multiple entries from one pipeline and multiple pipelines on the same day, keep each entry linked to its exact generated job, and preserve completed historical entries when a pipeline range changes.
- Calendar brief planning is an explicit token-consuming action. Show the number of briefs before confirmation, serialize model calls, persist per-entry pending/generating/ready/failed state, and create a different brief for each slot while excluding recent pipeline topics. A due entry may generate its missing brief immediately so a calendar run does not silently disappear.
- Keep pipeline color, brief source, topic focus, category, timezone, production template, and publishing policy aligned between durable state and the Automation UI. Deleting a pipeline removes future calendar entries but never deletes video jobs it already created.
- Default automations to human review. Automatic publishing must be an explicit saved policy with at least one connected destination; never infer it from selected platforms alone.
- Start independent platform uploads concurrently for both manual and automatic publishing. A slow processing or verification loop on one platform must not delay another platform from starting. Keep progress and failures isolated per destination, preserve successful results when another connector fails, and prevent a second publishing batch while the current batch is running.
- Keep HTTP validation, durable job state, concurrency, retry, stop, and recovery in `local-service/server.mjs` and `local-service/store.mjs`.
- Do not make one tool call another through HTTP. The UI composes workflows by referencing a completed tool job's asset.
- Add each new tool to both the server's `TOOL_DEFINITIONS` contract and the Tools UI. Give every required input its own selector.
- Classify FFmpeg-heavy operations as `media` and model-heavy operations as `model`. Preserve separate concurrency limits so users can submit many jobs without loading multiple local AI models into memory.
- Register spawned FFmpeg and Python processes with job control so Stop and shutdown release resources.
- Public-link tools must use the isolated downloader under `REELIO_DATA_DIR`, require public HTTPS URLs, reject loopback/private-network targets, disable playlists and external configuration, cap downloaded bytes, and explain that login-protected, DRM-protected, private, or unsupported sources cannot be imported. They must not depend on publishing OAuth.
- Inspect caption metadata before downloading, prefer exactly one matching manual track, and fall back to exactly one original automatic track. Do not use broad subtitle-language wildcards that download translated variants. Classify rate limits and missing impersonation support into concise user actions rather than exposing repeated downloader warnings.
- Build stock searches from contiguous visual story themes derived from the complete approved script. Do not regress to treating isolated subtitle lines as independent visual contexts.
- Normalize and search each repeated stock query only once per storyboard page, retrieve a pool large enough for every theme, and allocate media IDs uniquely across the whole storyboard. “Show different clips” must advance to another provider page rather than replaying the cached first page.
- Search every configured stock provider independently. A missing key, timeout, error response, malformed response, or empty result from one provider must not prevent another configured provider from supplying candidates. Merge and relevance-rank successful Pexels and Pixabay results with a modest diversity preference; do not blindly round-robin unrelated media.
- Cache successful stock-search responses under `REELIO_DATA_DIR` for 24 hours. Download only user-approved assets, retain the provider, creator, source URL, and exact license name, and show the provider on every storyboard result.
- Every storyboard theme may use one of three explicit modes: validated stock `media`, a durable local `custom` video upload, or a local `motion` background. Keep the file selector inside each theme and make a successful custom upload the approved choice for that theme.
- Upload custom storyboard videos through `POST /tool-inputs` and store them under `REELIO_DATA_DIR`. Persist only the returned `uploadId` and display `fileName` in `visualSelections`; never accept a client-supplied filesystem path.
- Validate custom upload references when `/jobs` is submitted and resolve them from the store again when a queued render starts. A missing custom video must fail with a clear error and must never silently become Pexels footage or a motion background.
- Only accept remote storyboard media from the provider-specific Pexels or Pixabay hosts validated in `local-service/validation.mjs`. Preserve the exact user-selected stock media, custom local video, or motion background for every theme during rendering.
- Keep custom storyboard videos local. Do not send their bytes, paths, filenames, or derived frames to Pexels or an AI provider. FFmpeg may crop, loop, and sample them locally to fill the approved theme's timeline slots.

## Tool contracts

- `chop`: default 180-second clips and 5-second overlap.
- `download-media`: supported public HTTPS video webpage or direct-media URL to a local video; the user must never need to discover the underlying MP4. No playlists, authentication, or DRM bypass.
- `extract-audio`: video to WAV or M4A.
- `extract-subtitles`: embedded text subtitle track to SRT and transcript without speech recognition.
- `extract-web-captions`: existing captions exposed by a supported public link to SRT and transcript without speech recognition.
- `transcribe`: audio/video to SRT and transcript using local faster-whisper. Start with VAD for normal speech; if it produces zero cues, retry once without VAD so singing and heavily mixed dialogue are not silently discarded.
- `translate`: SRT/VTT to translated SRT without changing cue times.
- `speech-synthesis`: timed subtitle cues to aligned narration.
- `video-synthesis`: source video plus translated audio and subtitles to MP4.

Tool outputs should remain immutable and reusable until their owning job is explicitly deleted. Tool inputs and custom storyboard uploads are durable local assets under `REELIO_DATA_DIR`. Validate every input reference again when a queued job starts because local files may be removed between submission and execution.

## Verification

Run `npm run check` before handing off changes. For media operations, include at least one real FFmpeg smoke test and keep pure timing or validation logic covered by fast unit tests. Script tests must verify that grounded specifics, caveats, the source index, selected structure, and angle plan survive into the drafting context. Storyboard tests must cover all three selection modes, missing/error/empty provider fallback, relevance-ranked provider diversity, provider-specific URL allowlists, malformed upload IDs, missing theme choices, and duplicate theme references.
